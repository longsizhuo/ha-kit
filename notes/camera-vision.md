# 摄像头视觉：判断人在哪个房间（待实施）

萤石 C6N 装在客厅，视野能覆盖各个房间门口。用它补上网络在场和 PIR 都答不了的
「人在哪个房间」——而且给的是**带方向的转换事件**（人往哪个房间去了），
正好接进现有的门锁事件驱动状态机：门锁管进出户门，摄像头管房间之间。

## 方案（已论证，未实施）

```
RTSP 辅码流 → 每分钟抓一帧 → YOLO 预训练权重检 person
  → 判断检测框底边中点落在哪个手画多边形里
  → 推回 HA：binary_sensor.主卧门口 / 厨房门口 / 厕所门口
```

**不需要**：树莓派、显卡、训练、标注、流分发。逐条说明：

- **不用加硬件**：每分钟一帧 = 0.017 FPS，mail 服务器的 8 核 i7 单帧几百毫秒就够。
  （我一开始判断「算不动」是按持续推理估的，按这个频率完全不成立。）
- **不用训练**：要检的是「人」，YOLO 的 COCO 预训练权重本来就有 `person` 类。
  分辨哪个门口**靠几何不靠模型**——区域是手画的多边形，不是学出来的。
- **不用流分发**：RTSP→WebSocket 那套是为多端实时观看，这里一次抓一帧即可。

## 开启 RTSP 的路径（很难找）

**不在摄像头的设置页里，在 App 的工具箱**：

```
萤石 App → 我的 → 工具 → 常用工具 → 局域网设备预览
  → 开始扫描 → 输入设备验证码（机身贴纸 6 位）
  → 设备设置 → 更多设置 → 本地服务开关 → 开启 RTSP
```

同时确认**「视频加密」已关**——开着时 RTSP 常出黑屏，最常见的坑。

地址格式（验证码即密码，用户名固定 admin）：

```
rtsp://admin:<验证码>@<相机IP>:554/h264/ch1/sub/av_stream    辅码流，优先用这个
rtsp://admin:<验证码>@<相机IP>:554/h264/ch1/main/av_stream   主码流
```

先用**辅码流**：分辨率低、码率小，抓帧场景够用，省带宽和 CPU。

## 为什么不走云快照

HA 内置 `ezviz` 集成能走云 API 抓快照，不用开 RTSP，但：

```
云快照   画面 → 萤石云 → HA → 本地      绕一圈，依赖外网
RTSP     画面 → mail 服务器             全程不出家门
```

摄像头是整套系统里**唯一能看到真实画面**的传感器。走本地的话，
出家门的只有「某门口有人」这个结论，画面一帧都不外流。

## 下一步（等人在家）

1. 按上面路径开 RTSP，记下验证码
2. 拉一帧下来看画质和视角，确认能看到几个门口
3. 划区域 → 装 ultralytics → 跑通 → 接进 HA

**第 2 步是唯一不确定的环节**（画质/视角够不够），先验证它，其余都是确定可行的。
