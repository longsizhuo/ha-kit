# HA 配置备份

`/opt/ha/config/` 里跟在场探测相关的配置，在这里留一份可读的副本（HA 本体在 docker 里，
配置目录 root 所有，不方便直接版本管理）。改了线上记得同步这里。

## automations.yaml

**回家欢迎仪式** —— 触发器用【门锁事件】而不是 `binary_sensor.someone_home`：
门锁 0 秒，网络判定实测滞后 98 秒，那一分半人已经在黑暗里站着了。
条件 `位置=2`（外侧）+ `动作=2`（开锁）已用双向带标注样本验证，见 `presence/lock-codes.md`。

### 灯：亮度分时段

```
天亮着          不开
18:00–23:00     亮度 180
23:00–06:00     亮度 60   ← 够看路、不刺眼、不吵醒人
```

这是「半夜回家灯全亮」那个 bug 的直接教训——米家原来的场景只有「设备接入」一个
干巴巴的触发器，加不了时段条件。

### 播报：艾露猫 persona

人设依据 `~/.hermes/SOUL.md` 与 `involution-hell-project/ChatBot/CLAUDE.md`。
硬约束三条，改文案时必须守住：

1. **一条消息最多一个「喵」**。第一版就违反过：温度句和问候句都带喵，组合起来是两个。
   现在喵只允许出现在主句，温度句和追加句一律不带。
2. **不能带 emoji**。persona 原文写了 ✨🐾 少量点缀，但那是文字场景；这里是 TTS，
   emoji 会被念出来或读成乱码。
3. **要短**。语音不是文字，每条控制在两句以内。

性格不只是句尾加喵（SOUL.md 明确说「人格不是一句句尾的喵」）。已用上的特征：
忠诚但笨拙（"数着数着都数糊涂了"）、会自我拆穿（"本来想装得淡定一点，好像没装成"）、
小小调皮（"零食还没偷吃完"）、孩子气（"尾巴都等直了"）。

### 「喵」的位置（用户偏好，2026-08-28）

用户明确要求：称呼用**老大**（正好是 persona 默认），且**喵要在结尾**。
所以整条消息的结构是：

```
问候句      不带喵
洗衣机提醒   不带喵（有则插在中间）
温度句      带喵，收尾   ← 唯一的喵，且是最后一个字
```

曾短暂改成按 ID 分流（本人叫「主人」、其他人叫「老大」），用户听过后否掉了，已撤回。

按「出门时长 ≥6h / <6h」×「室温 ≥28 度 / 舒适」分组随机，避免听腻。
**23:00–08:00 静音**，只开灯不出声。

改文案后务必抽样校验两件事：全条**只有一个喵**、且喵在**最后一句**。
